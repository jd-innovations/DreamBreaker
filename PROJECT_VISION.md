# DreamBreaker

## Vision

DreamBreaker is building the operating system for pickleball.

Our goal is not to create another tournament app.

Our goal is to build the platform that supports every part of a player's pickleball journey.

From the moment someone decides to play...

...until they leave the court...

DreamBreaker should be their companion.

---

# Mission

Help every pickleball player play more often, improve faster, build stronger communities, and understand their game through technology.

---

# Core Philosophy

The player is the center of the platform.

Not the tournament.

Not the court.

Not the club.

Everything exists to help the player enjoy and improve their pickleball experience.

Every feature should answer one question:

> "How does this improve the player's pickleball journey?"

# PAR

PAR stands for:

Pickleball Activity Rating.

PAR is DreamBreaker's proprietary player rating.

PAR measures demonstrated playing performance using complete pickleball activity.

PAR values transparency over complexity.

Players should always understand:

- Why PAR changed.
- Why PAR stayed the same.
- How confidence works.
- What improves PAR.

---

# My Stats

My Stats is the player's intelligence center.

It should answer questions like:

How am I improving?

Who do I play best with?

Where do I play best?

Which game format suits me?

What should I work on next?

How has my PAR changed?

No other pickleball application should provide deeper player analytics.

# Transparency

DreamBreaker should avoid "black box" systems.

If a feature produces a recommendation or rating, the player should understand why.

Trust is built through explainability.

---

# AI Philosophy

Artificial Intelligence should enhance the player, not replace decision making.

AI should:

Explain

Recommend

Summarize

Teach

Analyze

Never overwhelm.

Never invent player history.

Always remain grounded in available data.

---

# Technology Principles

Reuse existing architecture before creating new systems.

Avoid duplicate implementations.

Prefer extension over replacement.

Build modular systems.

Keep business logic separate from UI.

Design database models for future growth.

Everything should be testable.

Everything should be explainable.

---

# Engineering Principles

Before implementing new features:

Audit existing code.

Reuse existing components.

Reuse existing services.

Reuse existing database structures.

Only introduce new architecture when necessary.

Do not create duplicate profile systems.

Do not create duplicate match systems.

Do not fabricate missing data.

If backend functionality does not exist, expose an honest loading or empty state.

---

# User Experience Principles

Reduce friction.

Reduce taps.

Use intelligent defaults.

Use location intelligently.

Use context intelligently.

Use AI only when it provides genuine value.

The fastest path to playing pickleball should always win.

# Time to First Rally (TTFR)

One of DreamBreaker's primary success metrics.

Definition:

The amount of time between installing the application and successfully joining a pickleball game.

Every product decision should reduce TTFR.

Examples

Smart onboarding

Home Court suggestions

Nearby players

Nearby games

Community recommendations

Context-aware notifications

DreamBreaker is not building software for pickleball.
